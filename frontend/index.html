6 ขั้นตอน CRISP-DM

ขอบเขตงานเบื้องต้น

1. Business Understanding
กำหนดเป้าหมาย: ช่วยประเมินพื้นที่และช่วงเวลาออกเรือ
2. Data Understanding
ตรวจฟิลด์ เวลา หน่วย ความครบถ้วน และความสัมพันธ์ของ 7 collections
3. Data Preparation
รวม forecast ตามพื้นที่และเวลาที่สัมพันธ์กับเที่ยวเรือ ป้องกันข้อมูลรั่วไหล
4. Modeling
เลือก Features/Target แบ่ง train-test ตามเวลา ฝึก baseline และโมเดลเปรียบเทียบ
5. Evaluation
Regression: MAE/RMSE/R²; ตรวจผลเทียบ baseline และเป้าหมายธุรกิจ
6. Deployment
ภายหลังเชื่อมโมเดลกับ API และแสดงผลใน Dashboard พร้อมติดตามคุณภาพ

แนวทางโมเดลที่เสนอ

ต้องตรวจสอบความพร้อมของข้อมูลก่อนตัดสินใจ

ตัวเลือก A — พยากรณ์ปริมาณสัตว์น้ำ
Target: ปริมาณจับต่อเที่ยวเรือจาก fishing_trips/catches
Features ที่เป็นไปได้: พื้นที่ เรือ และค่าพยากรณ์อากาศ/ทะเลก่อนออกเรือ
โมเดลเริ่มต้น: Linear Regression เทียบ Random Forest Regressor

ตัวเลือก B — คะแนนความเหมาะสมของพื้นที่
เริ่มจากเกณฑ์ Rule-based ที่อ้างอิงได้ก่อน ไม่เรียกว่า Machine Learning จนกว่าจะมี Target ที่เชื่อถือได้

ข้อจำกัดสำคัญ
หากไม่มีตัวอย่างเที่ยวเรือที่ยกเลิกหรือไม่ออกเรือ ยังไม่ควรฝึก Classification เพื่อทำนาย “ควรออกเรือ/ไม่ควรออกเรือ”

สถาปัตยกรรมที่ใช้งานอยู่

Dashboard → FastAPI → MongoDB

1. Backend API
FastAPI (backend/main.py) อ่านข้อมูลอย่างเดียว ไม่มี URI/รหัสผ่านในหน้าเว็บ และจำกัดจำนวนรายการต่อหน้า

2. Data validation
API ตรวจพารามิเตอร์ (หน้า ช่วงวันที่) ค่าที่ว่างใน DB ถูกแสดงเป็น "ไม่มีข้อมูล" ไม่ถูกแทนด้วย 0

3. Refresh
โหลดตอนเปิดหน้าและเมื่อกดปุ่มรีเฟรช ยังไม่มีการดึงอัตโนมัติ

4. Forecast data
src/09_fetch_forecast.py ดึงพยากรณ์จาก Open-Meteo ไปเก็บใน weather_forcasting เป็นรอบ (รันแยกต่างหาก)
เบราว์เซอร์เรียก API ที่ http://127.0.0.1:8000 เท่านั้น ไม่เชื่อมต่อ MongoDB โดยตรง ต้องเปิดหน้านี้ผ่าน HTTP server ในเครื่อง (เช่น พอร์ต 5500) ไม่ใช่ file://
